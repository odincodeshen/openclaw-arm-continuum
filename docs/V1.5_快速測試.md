### C2. 決定性路由仍然優先（Telegram）

| 傳 | 預期 | 為什麼 |
|---|---|---|
| `/rag #AI應用 重點` | 走 RAG，**不經** router | slash 指令優先 |
| `明天天氣如何` | 走天氣，**不經** router | 關鍵字優先 |
| `/mem 記一下` | 走 memory | slash 優先 |

### C3. 自然語言殘差 → router 分類

沒有 slash、沒有關鍵字的問句：

| 傳 | 預期 |
|---|---|
| `我之前上傳的那份文件裡有寫到 HAL 嗎？` | 被分類成 knowledge_base → 走 RAG（會有「來源：」行） |
| `NVIDIA 最近發表了什麼新晶片` | 被分類成 web_search → 走搜尋 |
| `幫我想三個週末活動點子` | 分類成 chat → 一般模型回答（跟以前一樣） |

看判斷過程：`docker compose logs openclaw-telegram | grep runtime` 看
`agent=rag_agent` / `browser_search_agent` / `chat_agent`。

## D 層：完整 3-model catalog — /review + 專家模型（規格 3a + v1.3）

需要 `local_router` + `local_coder` + `local_reasoner` 三個端點都起來。
參考 `docs/DGX_V13_VALIDATION.md`。

### D1. engineering_review agent 載入

```bash
! docker compose exec -T openclaw-telegram python -c "import openclaw_telegram_gateway as g; print([a.name for a in g.agent_registry.agents])"
```

- **預期**：清單多了 `engineering_review_agent`。

### D2. `/review`（Telegram）

- 傳：`/review <一段去識別化的工程設計描述或程式片段>`
- **預期**：先 route（分類），再跑 code_review + architecture_review，
  最後 synthesis。一輪約 300–450 秒（看 `docs/ENGINEERING_REVIEW_REAL_MODEL_VALIDATION.md`）。
- `/tasks last` 應看到子任務、`model_policy`、`endpoint_id`。
- task_history 不會存 `/review` 的輸入原文（redacted）。

### D3. fallback

- 停掉 `local_coder` 端點，再跑一次 `/review`。
- **預期**：code_review 自動 fallback 到 `local_default`，回覆開頭標
  `DEGRADED REVIEW`，`/tasks` 記錄 `fallback_from: local_coder`。

### D4. per-skill 專家模型（規格 3a）

- `app/skills.json` 把 `rag_retrieve` 的 `"model_policy"` 改成
  `"local_reasoner"`，重啟。
- 傳 `/agents`
- **預期**：`rag_agent` 那行顯示 `(local_reasoner -> <endpoint id>)`。
- 傳 `/rag #AI應用 重點` → 答案由 reasoner 產生（通常更完整、較慢）。

☐ D 層通過

## 出問題時

- `docker compose logs -f openclaw-telegram` 看 `[category]` / `[vision]` / `[runtime]` / `[skills]` / `[agents]`
- catalog 格式錯 → 容器啟動會直接失敗並印 `invalid model catalog JSON` 或 role 錯誤訊息
- `models.json` 在 `app/models.json`（已被 gitignore），`/app` 是唯讀掛載，改完要 `docker compose restart openclaw-telegram`
